# 第六轮：E10.5 心脏文库 + 20% 校正后的 E14.5 细胞核（2026-11-26）

## 结论

推荐的第二次官方提交是 `round6_heartlib_anchor0.2_harm1_trend0`，共 4,000 个细胞：

- 3,200 个取自 E10.5 的心脏文库，下称基底。E10.5 有三个 10x 文库，这是心脏谱系细胞占 94% 的那一个（本文的心脏谱系含血细胞和巨噬细胞，不算血细胞是 78%；细胞条码后缀 `_3`，下称文库 3）。细胞按自然比例不放回随机抽取，表达值不改。
- 800 个是公开的 E14.5 野生型小鼠心脏细胞核，下称锚点，意思只是混进预测文件的后期真实细胞核（GEO GSE272154 / GSM8394736，和竞赛数据同为 10x Multiome、Cell Ranger ARC 2.0.2、mm10）。它们占 20%，混入之前先去掉它们和 E10.5 心脏文库之间“各谱系共有”的那部分差别，下称校正。

文件 SHA-256 为 `d73f82265953d878ec2e77fae7895b91c8f96f7222d1abca80c0e8459fc27bd5`，已通过 `validate_prediction(path, "T1:test")`。

它和第五轮文件（`round5_anchor0.375_all_h1`，SHA-256 `7855b636c13b7de3661f3588096cdaabebe34bd088a15599dce06251e7997ee0`，下称 R5）差三处。第一，基底从第四轮的做法（按 bulk 趋势反卷积出细胞类型比例，从 E10.5 全部三个文库里抽细胞，再改动表达值，见“第五轮基底的问题”）换成文库 3 的自然比例。第二，锚点先校正再混入。第三，锚点比例从 37.5% 降到 20%。锚点的来源没有变。下文把这份候选叫 R6；锚点仍占 37.5% 的版本是第一次独立审查（见文末）之前的定稿，下称 R6 第一版。进展日志里把这两份分别记作 R6b 和 R6。

我们用已公开的三个阶段搭了一组本地代理任务（下称代理，见“验证套件”）。每个代理有参考、源、目标三样，只在某一方面模仿测试。每个目标的细胞分成互不重叠的两半，一半用来调参（选模集），另一半每个定稿配置只打一次分（复核集）。除了标明测试榜、公开榜、验证榜的数，本文的分数都是本地校准分：在某个代理里，把参考阶段的细胞原封不动交上去得 50 分（下称地板），目标的另一半细胞得 100 分（下称天花板）。它们不是榜单分。

R6 要替换 R5，须在复核集上满足三条事先写定的条件（见“替换规则和复核结果”），结果三条都满足。但起决定作用的证据都没有时间差。一类是照搬测试的参考和源、拿 E10.5 文库 3 的一半当目标的四个情景（情景表），R6 的基底就取自这个文库，占优是设计使然。另一类是从 E10.5 另两个文库预测文库 3（代理 D），R6 在那里用的是另两个文库里带心脏谱系标签的细胞，占优不是设计出来的，但同样没有时间差。目标比源晚的本地代理里，目标是 E10.5 的七个都是 R5 更高（复核集上 R6 低 6.3 到 14.3 分），只有 E8.5 → E9.5 的 gen 上 R6 高 1.30；拿外部 E14.5 心脏当目标、只比基底（TE），也是 R5 的基底更高（见“对 R6 不利的证据”）。本地没有任何代理同时具备“源阶段自带心脏文库”和“目标晚两天”。

所以推荐 R6 是一次判断：它押的是“E12.5 像同一实验室的心脏文库，再往 E14.5 走一小段”。依据有两条：官网说明 E12.5 是专门切出的心脏；R5 基底里决定细胞组成的那一步（bulk 趋势反卷积）已经在测试榜上交过一次（第一次官方提交 h1，榜单分 70），没有显出本地代理预告的增益。粗略假设 E12.5 落在两类证据的正中间，R6 的基底对 R5 的基底的优势是几分的量级，集中在 E12.5 测序不浅、确实切得干净的情形；E12.5 若测得浅，或者和 E10.5 一样带周边组织，R6 的基底不占优甚至吃亏（数字见“E12.5 落在两类证据之间时的粗估”）。R6 和 R5 两份文件都已放在 mbp2，R5 是备选。

## 测试榜的参考阶段

测试榜（T1:test，目标 E12.5）的参考阶段是 E9.5，50 分基线是把 E9.5 原封不动交上去。评分里有两项是相对参考阶段算的（见下一节），所以它们量的是 E9.5 → E12.5 的变化，本地应当优先看“参考阶段在源阶段之前”的代理。依据有四条：

1. **官网对 copy_last 的定义**：官方把 copy_last 这条基线定为 50 分。Reference rows 页写 “Predict the last observed stage, verbatim”，“Returns the final training stage’s cells as the prediction”。任务页写 “Train: E8.5 · E9.5”，E10.5 是验证阶段。
2. **官网对评分器的说明**：Data 页写 “the scorer subsamples every stage to 10% before comparing anything. E9.5 as released holds 17,057 cells; the scorer's reference stage is 1,706”。
3. **细胞数上限的算法**：官方 `panels/index.json` 里 T1:val 的 `ref_cells` 是 1706、`max_cells` 是 5118；T1:test 的 `max_cells` 也是 5118，`min_cells` 是 638。官网 Data 页在 11-17 之前写过上限怎么算（社区仓库 xxx12e/vec-community-kit 的 `rules-watch/CHANGES.md` 逐日存档了官网的改动，这句引自它 11-17 的条目）：“It is set at three times the larger of the board's truth half and its reference stage, with a floor of 5,000.” 5118 = 3 × 1706，所以测试榜的参考阶段是 1,706 个细胞，即 E9.5 的 10%。参考阶段若是 E10.5（24,979 个细胞的 10% 是 2,498），上限应为 7,494。
4. **公开榜的分布**（旁证）：公开测试榜前 200 名的 DES 技能分都在 61.8 以上、DCS 在 75.8 以上；冻结的验证榜（参考 E9.5、目标 E10.5，当时没有人手里有 E10.5）上 DES 最高 66.5、中位数 51。测试榜上人人都有 E10.5，如果参考是 E9.5，交 E10.5 的细胞就已经报对了 E9.5 → E12.5 的大半变化，这两项普遍偏高说得通；如果参考是 E10.5，从 E10.5 重抽样的预测在这两项上应当贴近地板。我们第一次提交用的就是从 E10.5 重抽样的细胞，得 70 分。

第五轮日志里引过“E10.5 原封不动提交约 69.4 分”，这次没有找到出处，不再作为依据。

## 评分的四项指标

官方评分有四项，括号里是分数表的列名和权重。DES（差异表达分，`skill_de_score`，25%）看目标相对参考阶段变了的那批基因有没有报对。DCS（方向一致分，`skill_de_direction`，25%）看全转录组的变化方向对不对。MMD（最大均值差异，`skill_mmd_u`，30%）在目标自己的 30 维主成分空间里比较两群细胞的分布，细胞状态和比例都要对。CSS（共表达结构分，`skill_variogram`，20%）比较基因两两之间的共变结构，对测序深度敏感。每项先换成技能分：地板是 0.5，达到天花板是 1；总分是四项技能分按权重相加再乘 100。

**代理里的 R5 和 R6 指做法**：表里的“R5”是 R5 的做法在每个代理自己的细胞池里重做一遍（反卷积、改动表达值、未校正的锚点），不是第五轮那份文件本身；“R6”是 R6 的配置换上代理的输入。R6 的基底按目标的取材来：目标是心脏文库，就用源阶段的心脏文库，源阶段没有心脏文库（E8.5、E9.5、E10.5 的文库 1+2）时用带心脏谱系标签的细胞；目标和源取材相同，就用全部细胞。锚点比例在有时间差的代理里按“ρ × 时间比例”取，R5 的 ρ 是 0.75，R6 是 0.4，所以 D 不加锚点；情景表模仿测试，直接用测试时的比例（R5 37.5%，R6 20%）。

**两半和打分**：每个目标拆成互不重叠的两半，一半作选模集（代码里叫 development），另一半作复核集（confirmation）。在一半上打分时，地板用该代理的参考阶段，天花板用同一目标里另外留出的一份细胞。

**重采样噪声**：同一配置换 5 个抽样种子，标准差是 gen 0.7 到 1.1，p8/deep 和 p8/all 0.6 到 0.9，2d 两个 0.2 到 0.4，D 两个 0.2 到 0.3，情景表 0.2 到 0.4（R5 基底的抽样种子在第五轮代码里写死，R5 的噪声被低估）。同一配置在选模集和复核集上的分数平均差 0.5，最大差 1.6。下文把 1 分以内的差别当平手。

## 第五轮基底的问题

R5 的基底（下称第四轮基底）分三步。第一步是第二轮的做法：用 E9.5 和 E14.5 的 bulk RNA-seq 估一个基因趋势，用非负最小二乘找一组细胞类型比例去拟合它（下称反卷积），按这组比例从 E10.5 三个文库里抽细胞。第二步把抽到的细胞按 bulk 趋势逐基因缩放。第三步把各基因的平均表达平移到“参考阶段的均值 + bulk 趋势方向和反卷积方向的加权和”（下称基因方向平移）。后两步是第四轮加的；第一次官方提交 h1 只有第一步。反卷积强度、ridge 和平移的权重，都是在 E9.5 → E10.5 这一条转移上挑的。换到别的设定，它的表现是这样：

- **没调过参的转移（gen，E8.5 → E9.5）**：选模集上，只做第一步是 50.76（地板 50.00），其中 MMD 和 CSS 的技能分是 0.403 和 0.403，低于地板的 0.5，靠 DES（0.591）和 DCS（0.633）拉回。三步都做是 52.15（另一次抽样 52.39），和从 E8.5 按自然比例抽的细胞（52.24）持平。复核集上三步都做是 53.53，自然比例是 51.79。两半合起来，第四轮基底在这条转移上的增益在 −0.1 到 +1.7 之间，和噪声同量级；它在 → E10.5 代理上的增益是 10 分上下。
- **只有取材变化（D）**：从文库 1+2 预测文库 3 时（选模集），带心脏谱系标签的细胞按自然比例抽是 61.94（D/raw）和 79.02（D/dm），第四轮基底是 56.97 和 72.32，全部细胞按自然比例抽是 53.19 和 65.94。
- **测试榜**：h1 得 70 分。公开榜上名字像“E10.5 稍作处理”的条目在 72.2 到 72.9（`t1_mix_e105_w75`、`shift_E105_c3000`、`per-type pseudobulk shift; base=E10.5 RNA`）。这些条目的具体做法我们不知道，只能说 h1 没有显出本地 → E10.5 代理预告的 10 分。

在每个代理里，谱系组成都是影响分数最大的一项。把基底按目标的真实谱系比例抽（下称 oracle 基底，只用于分析，不是可提交的做法），不加锚点就比自然比例高 7.2（gen）、14.6（p8/deep）、8.9（p8/all）、13.2（2d/deep）、8.9（2d/all）、15.3（D/raw）、18.0（D/dm）。第四轮基底在 p8/deep 上（72.29）接近 oracle 基底（74.33），这是它调参用的转移。

官网 Data Protocol 对两个阶段取材的原话是：E10.5 “Heart tube collected with surrounding structures”，E12.5 “The hearts were dissected more specifically, with most of the surrounding tissue removed”。E10.5 的三个文库里，文库 3 有 94.3% 的细胞属于心脏谱系（心肌、心内膜 / 内皮、心垫间充质、心外膜、血细胞、巨噬细胞），文库 1 和 2 分别只有 47.2% 和 42.9%；E8.5、E9.5 的四个文库在 37% 到 48% 之间。R6 因此直接用文库 3 的自然比例做基底。

## 锚点校正

锚点来自另一个实验室，校正的目的是去掉两家数据之间和发育无关的差别。做法是：把每个锚点细胞核归到最相近的 E10.5 细胞类型，再并成四个谱系（心肌、心内膜 / 内皮、心垫间充质、心外膜）；对每个基因，分谱系算“E10.5 心脏文库平均计数 / 锚点平均计数”的自然对数比；四个谱系同号时，取其中绝对值最小的那个作为共同差别，把锚点细胞核里这个基因的计数乘上对应倍数（最多 e^3 倍），再把每个细胞核归一化回 10,000。四个谱系不同号的基因不动，谱系之间不一样的那部分差别也不动，零值保持为零。校正用到的只有锚点本身和抽基底用的那批源阶段细胞（导出时是文库 3 的全部细胞，代理里是该代理用作基底的细胞）。换 1、6、8、10 个线程重算，锚点的谱系归属和校正量逐位一致（`round6_threadcheck.py`）。

导出时有 10,629 个基因带共同差别，其中 2,055 个超过 0.5（按自然对数比的绝对值，下同），391 个超过 1。里面能认出三类和发育无关的差别：

- **两家细胞核带的胞质 RNA 量不同**：核糖体蛋白等胞质高丰度 mRNA 在锚点里低很多（83 个核糖体蛋白基因的共同差别平均 1.23；Rps2、Eif5a、Hsp90ab1、Rpl4、Npm1 在 1.7 到 2.2 之间），长基因偏高。
- **锚点没有去环境 RNA**：成体珠蛋白（Hbb-bs 4.35、Hbb-bt 2.94）、心肌基因（Ckm、Mb）、内皮基因（Fabp4、Cd36）在锚点的每个谱系里都偏高；竞赛数据用 SoupX 去过环境 RNA。
- **锚点是单一性别的样本**：几乎没有 Xist（2.9）。

这部分共同差别里也有真实的、各谱系一起发生的变化，例如胚胎型珠蛋白在 E14.5 更低（Hbb-bh1 3.19、Hba-x 1.73），增殖和蛋白合成相关基因下降。校正把这些也一起去掉了，这是它的代价。

校正在两类证据上方向相反（复核集）。没有时间差的情景表里，R6 比“R6，锚点不校正”高 3.12（心脏/深）、3.73（中）、2.24（浅）、1.11（全部文库）。有时间差的 8 个代理里，按各自的小比例混入时，校正在 7 个上是亏的：配 R6 的基底低 1.0 到 2.3 分，配 R5 的基底低 0.3 到 1.2 分，gen 例外（+0.45 和 +0.62）。所以校正的得失取决于 E12.5 的发育进度：E12.5 如果离 E14.5 还远，它减少外来细胞核的代价；如果 E12.5 的发育进度和这些代理一样，它要付 1 到 2 分。

## 对 R6 不利的证据

**7 个 → E10.5 代理**：复核集上 R6 比 R5 低 6.26 到 14.31 分。其中五个（p8/deep、p8/all、raw、h3、dm）的差距主要在基底：都不加锚点时，R6 用的细胞比 R5 的基底低 9.9 到 13.9 分（p8/deep 是 60.34 对 72.15）。2d/deep 和 2d/all 的基底只差 1.7 和 6.0，其余来自锚点比例减半和校正（2d/deep 上锚点带来的增益，R5 是 +10.83，R6 是 +6.32）。基底这一项的原因是 E9.5 → E10.5 这一步心脏内部的组成变了：心肌占心脏谱系细胞的比例从 E9.5 的 64% 掉到文库 3 的 20%，血细胞从 3% 升到 17%。R5 的反卷积在这条转移上调过，跟上了这次变化（选模集 p8/deep 上 72.29，oracle 基底是 74.33）；“E9.5 心脏细胞的自然比例”跟不上。测试时 R6 用的是文库 3 自己的比例，不依赖 E9.5 的比例，这一条亏损不直接搬到测试上；但它说明，如果 E10.5 → E12.5 心脏内部组成再大变一次，R6 也会吃亏。

**TE**：对着外部 E14.5 样本先只比基底（复核集）：文库 3 的自然比例是 61.28（原始深度）和 60.85（深度匹配），第四轮基底（用全部文库）是 66.10 和 65.09，E10.5 三个文库按自然比例抽是 63.99 和 63.12。各自再加 37.5% 同一外部样本里不在目标中的细胞核，文库 3 是 82.18 和 82.32，第四轮基底是 85.35 和 84.81。把目标也校正成“像竞赛实验室做的”以后顺序不变（选模集，原始深度，不加锚点：文库 3 62.29，第四轮基底 68.26，三个文库自然比例 65.71）。也就是说，对一颗四天后的、别的实验室的心脏，第四轮基底比文库 3 高 2.5 到 4.8 分。

这个差距能拆成两部分（选模集）。一部分是深度：目标测得浅（UMI 中位数 3,059），浅细胞在 CSS 上占便宜。让文库 3 和文库 1+2 的心脏细胞按相同的谱系配额各抽一份，原始深度下文库 1+2 高 2.34（63.47 对 61.13），深度匹配后只高 0.59（61.03 对 60.44）。另一部分是反卷积本身：同一个细胞池里，第四轮基底比自然比例高 1.8 到 2.7（TE/raw 上用全部文库是 66.10 对 64.04，只用文库 3 是 63.41 对 61.29），说明对着 E14.5 的心脏，朝 bulk 趋势调组成是有用的。还有一小块没解释：深度匹配后，三个文库的心脏细胞按自然比例（62.65）仍比文库 3 的心脏细胞（60.59）高 2.1，而谱系配额相同时只差 0.6。

## 四项指标的分解

**基底（R5 的基底 → R6 的基底，都不加锚点，复核集）**：D/dm 上 DES 0.592 → 0.663，DCS 0.738 → 0.799，MMD 0.723 → 0.807，CSS 0.845 → 0.883，四项都升。情景表“心脏/深”上 DES 0.738 → 1.000，DCS 0.834 → 1.000，MMD 0.768 → 0.995，CSS 0.583 → 1.000；这一格的预测和目标来自同一个文库，接近满分是设计使然，用来对照 R5 的基底差多少。CSS 差得最多，因为 R5 的基底有一半细胞来自浅文库。gen 上（R6 用的是从 E8.5 按自然比例抽的细胞）DES 0.509 对 0.576，DCS 0.552 对 0.631，MMD 0.506 对 0.467，CSS 0.504 对 0.468，即第四轮基底在方向类的两项上高、在分布类的两项上低，总分 51.79 对 53.53。

**20% 的锚点（R6 不加锚点 → R6，复核集）**：有时间差的代理上四项都升，例如 p8/deep 从 60.34 升到 64.97（DES 0.579 → 0.617，DCS 0.690 → 0.727，MMD 0.597 → 0.641，CSS 0.534 → 0.608），2d/deep 从 53.39 升到 59.71，gen 从 51.79 升到 55.49。情景表“心脏/深”上方向相反：DES 1.000 → 0.872，DCS 1.000 → 0.950，MMD 0.995 → 0.914，CSS 1.000 → 0.791。锚点的增益出现在目标比源晚的时候。

**校正（R6，锚点不校正 → R6，复核集）**：情景表“心脏/深”上 DES 0.825 → 0.872，DCS 0.934 → 0.950，MMD 0.885 → 0.914，CSS 0.755 → 0.791，四项都升；我们的理解是校正后的细胞核更像竞赛数据里的细胞。p8/deep 上四项都略降：DES 0.629 → 0.617，DCS 0.740 → 0.727，MMD 0.648 → 0.641，CSS 0.614 → 0.608。我们的理解是，各谱系共有的差别里也混着真实的整体发育变化，校正把它一起去掉了；目标比源晚时，这点损失大于前一种收益。

每个配置在每个代理上的四项技能分都在 `scores/` 的表里。

## 独立复核

### 第一次：泄漏、合规、代码

R6 第一版导出之后，请了一个没看过本文结论的审查员，只给代码、分数表和规则原文，不许改文件，让它查泄漏、外部数据合规、导出和验证是不是同一条代码路径，以及代码错误。它的发现和处理如下。

**情景表在构造上偏向 R6，它的加权数不能当作 E12.5 的预期分（对结论影响最大的一条）**：审查员指出，情景表和 D 的目标就是 E10.5 的文库 3，R6 不加锚点时在“心脏/深”上得 100 分是必然的；凡是 → E10.5 的代理和 TE 都是 R5 更高；R6 得到的支持只来自没有时间差的设定，外加第一版在 gen 上一个噪声以内的平手（+0.44）。这条意见成立。处理有三项。一，结论和“替换规则”一节直接说明这一点，加总数不叫预期分，并给出“E12.5 落在两类证据之间时的粗估”。二，补做了 TE 的文库对照实验，查清“只取文库 3 更差”里有多少是深度。三，顺着同一个道理重看锚点比例，把它从 37.5% 降到 20%（见“锚点比例”）。基底的推荐没有改，理由写在“对 R6 不利的证据”末尾。

**一处潜在泄漏（没有影响任何已存的表）**：`round6_suite.py` 里 TE 的目标取自外部 E14.5 样本的一部分，而 `round6_final.py`、`round6_s1.py`、`round6_s2.py`、`round6_tilt.py` 混锚点时是从整个样本里抽的。如果有人通过这几个脚本去跑 TE，目标细胞核会混进预测。审查员逐个核对了分数表，TE 只通过 `round6_te.py` 跑过，那里只从不在目标里的 1,481 个细胞核里抽。处理：`Suite` 现在拒绝 TE，除非调用方显式声明只从目标外的细胞核里抽。

**校正的说法不准确**：方法说明原来写“谱系特有的差别即发育信号被保留”。审查员指出各谱系共有的差别里也有真实变化（胚胎型珠蛋白、增殖相关基因），而且校正在 8 个有时间差的代理里的 7 个上是亏的，只在没有时间差的情景表里赚。处理：方法说明和“锚点校正”一节照此改写。

**自检太弱**：原来的自检只比分数，容差还从 1e-6 放宽到了 1e-3。处理：情景表现在把每个配置的预测细胞存一个 SHA-256，导出脚本重算后比的是细胞本身（逐位一致），分数只作附带核对；确定性检查改为重新计算校正量，不再读缓存；另外验证了锚点谱系归属和校正量在 1、6、8、10 个线程下逐位一致，之前 4e-6 到 1.3e-5 分的差别来自评分器的浮点求和。

**代码在审查期间还在改，清单里的代码哈希对不上**：全部改完后，用最终代码把第一版的选模集情景表和十个代理重跑了一遍，和原表逐格相同（最大差 0）；`manifest.json` 里记的是最终代码的哈希，和仓库里的文件逐个核对一致。

**其余几条小问题**

- 表里的“R5”是 R5 的做法在代理的细胞池里重做（情景表里 1,250 个基底细胞 + 750 个锚点细胞核，反卷积在 11,486 个不含目标的细胞上做），不是第五轮那份 3,200 个细胞的文件本身。已在“验证套件”一节注明。
- 换种子估噪声时，R5 基底的抽样种子在第五轮代码里是写死的，所以 R5 的噪声被低估；多种子运行如果不加标签会覆盖主表，现在不加标签会直接报错。
- 三行对照配置和别的行相同，已从代码里去掉（第一版的复核集原始表里还留着）。
- 校正量的缓存原来只按调用方给的字符串取，现在按源阶段和细胞池本身取。
- `round6_s1`、`round6_s2`、`round6_d2`、TE 的校正目标这几次探索跑在较早的代码上（校正多用一个巨噬细胞谱系），不影响定稿的表。
- 几个非候选代理的预测里用到了和目标有关的量：dm 把源稀疏到 E10.5 的深度分布（含目标细胞），TE/dm 把源稀疏到整个外部样本的深度分布，TE 的校正目标实验用整个外部样本估校正量，`round6_d2` 里“各文库心脏细胞的自然份额”数了目标细胞的标签。这些都到不了候选配置和导出。

审查员确认没有问题的部分：情景表和各代理的预测细胞与目标、天花板细胞没有交集（情景表的细胞池 11,486 个，和 9,021 个目标细胞交集为零）；oracle 基底只在 `round6_s1`、`round6_s2`、`round6_tilt` 里用到，定稿评估、配置、导出都不读它；导出只依赖 E10.5 文件、外部 E14.5 样本、官方基因表和随机种子，没有任何常数来自榜单分数或 E12.5。竞赛规定外部数据不能取自 E9.5 之后到 E13.5（含）的阶段。外部样本逐个在 GEO 上核对过（GSM8394736：E14.5、野生型、胚胎心脏、10x Multiome；GSM6943750–52：E9.5，GSM6943761–63：E14.5，野生型 C57BL/6 心脏 bulk；GSM6211349 只用了基因名表），都不在这个范围里；代码用写死的文件名读它们，同系列里 E10.5、E12.5 的样本没有下载。R6 定稿不用 bulk 数据，只用 GSM8394736。

审查员没能检查的：主办方评分器的随机种子和代码版本；另外两台电脑（mini 和 mbp2）上有没有禁用的外部文件，它只查了跑实验的宿舍机和下载脚本；以及任何关于 E12.5 真实组成的事。
